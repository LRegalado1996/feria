# Languages

The product speaks Spanish and English. Read this before you add interface text, a page, a link between pages, or anything that formats a number, a price or a date.

## The URL decides the language

- **Spanish has no prefix, English lives under `/en`:** `/products` and `/en/products` are the same page. The locale never comes from a cookie, the session or `Accept-Language`: a link sent by WhatsApp opens in the language it was sent in.
- Pages live under `src/app/[locale]/`, whose `layout.tsx` is the root layout: it sets `<html lang>`, and `generateStaticParams` lists both languages so every shell is prerendered once per language. Only `api/` and `global-error.tsx` sit outside it.
- `src/proxy.ts` gives each page request its route: an unprefixed path is rewritten to `/es/...` (the address bar keeps the short URL), `/en/...` passes through, and `/es/...` redirects (308) to the unprefixed URL, so a Spanish page has one address. It only stamps `/api` requests for logging, and its `matcher` leaves out Next's assets, Vercel's endpoints, the Sentry tunnel and each file in `public/` by name: a file added to `public/` is added to the matcher too (a test in `src/proxy.test.ts` fails until it is), or the proxy rewrites it into a 404.
- `src/app/[locale]/[...rest]/page.tsx` answers every unknown address with `notFound()`, so a 404 renders inside the app's shell, in the visitor's language. The status is 404 from the server; the page's text is rendered by the browser, because the prerendered shell of a route that always throws is empty.
- A standalone server bound to one address (`HOSTNAME=127.0.0.1`) treats the proxy's rewrite as a request to another host and loops through the `/es` redirect. Bind to `0.0.0.0`, the default and what containers use.
- `src/lib/i18n/config.ts` holds `LOCALES`, `DEFAULT_LOCALE`, the `Locale` type and `isLocale()`. A route param is any string: every layout and page gets its language with `readLocale(params)` (`src/lib/i18n/read-locale.ts`), which answers 404 for anything else.

## Links between pages

- **Build every internal path with `localizePath(path, locale)`** (`src/lib/i18n/paths.ts`): a bare `href="/"` sends an English visitor to Spanish. The same goes for `window.location.assign()` after signing in or out.
- The locale toggle (`molecules/locale-toggle`) is a link to the same path and query string in the other language. After a soft navigation the page left behind stays mounted and hidden (`docs/agents/nextjs.md` § Navigation), so a test targets the visible toggle.
- A page declares its canonical URL and `hreflang` alternates from its own `generateMetadata` with `buildAlternates(path, locale)` (`src/lib/i18n/metadata.ts`). A layout cannot: it does not know the page's path. They resolve against the root layout's `metadataBase`.

## Interface text

- **No interface text in a component, a hook or a schema.** Every string a person reads or a screen reader announces (labels, placeholders, `aria-label`, toasts, validation messages, document titles) lives in `src/content/{es,en}/`, one file per area.
- Spanish is the source of the shape: `src/content/es/index.ts` exports `Dictionary`, and every English file is annotated with its slice (`Dictionary["auth"]`). A key missing from either language, or present in only one, fails `pnpm typecheck`.
- **Server components** call `getDictionary(locale)` from `@/content` with the locale they got from `params` (or receive the slice they need as a prop). The module is `server-only`.
- **Client components** call `useDictionary()` and `useLocale()` from `@/lib/hooks/i18n`. The root layout feeds them through `AppProviders`, so only the language on screen reaches the browser. Outside the provider they throw: a silent fallback would show the wrong language.
- A string that takes a value is written with a placeholder (`"Delete: {row}"`) and filled with `interpolate()` (`src/lib/i18n/interpolate.ts`). Dictionaries hold strings, never functions: they cross from the server to client components.
- A zod schema whose messages are shown under a field is a factory that takes its messages (`createAuthSchema(dictionary.auth.validation)`). A schema that only guards a procedure keeps plain English messages: `design.md` already forbids showing a raw `error.message`.
- `global-error.tsx` replaces the root layout, provider included, so it imports its own few strings in both languages and reads the locale from the route params.
- Spanish copy uses the Rioplatense voseo ("Probá de nuevo", "Iniciá sesión"): the first stores are Uruguayan.
- Content from the database (store names, articles, categories) is not interface text: it is translated in `*_translation` tables (`docs/project/overview.md`). A page picks the row to show with `pickTranslation(rows, locale)` (`src/lib/i18n/pick-translation.ts`): the visitor's language, else the one that exists. It sets `lang` on the element from the row it got, because that can be another language than the page's.

## Numbers, prices and dates

`src/lib/utils/format.ts` owns every `Intl` formatter, cached per language. Each function takes the locale as an argument; nothing reads an app-wide language.

- `formatPrice(amountInMinorUnits, currency, locale)`: `$ 1.290` and `US$ 12,50` in Spanish, `UYU 1,290` and `USD 12.50` in English (a bare `$` does not tell a visitor from abroad pesos from dollars). Cents show only when the amount has any; nothing is rounded on screen.
- `formatInteger(value, locale)`: a count with the language's grouping (`1.280`, `1,280`).
- `formatDate(date, locale)` and every other date format in `APP_TIME_ZONE` (`America/Montevideo`), never the host's zone.
- `formatRelativeTime(date, now, locale)` takes the clock as an argument (`docs/agents/nextjs.md` § Hydration).
- `toPlainNumberText` and `fromPlainNumberText` convert between what a person types ("1.500,5" in Spanish) and what `Number()` reads. `atoms/input` uses both for `type="number"`.

## Tests

- `src/test/i18n.tsx`: `renderWithI18n(ui, { locale })` and `createI18nWrapper(locale)` mount the provider; `DICTIONARIES` holds both languages. The default is English, so assertions read in the language of the code; **every component with text also has a case rendered in Spanish**, which is what catches a string hardcoded in either language.
- A server component's test mocks `server-only` (`vi.mock("server-only", () => ({}))`) and passes the locale or the dictionary in.
- E2E page objects read the interface in Spanish, the default. `src/e2e/tests/i18n.e2e.ts` covers English, the toggle, `<html lang>`, the redirect and the alternates.
