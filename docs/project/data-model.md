# Data model

First draft. Each table is finalized in the ticket that creates it. Template rules apply: no JSON columns, 3NF, singular snake_case tables, camelCase columns, integer identity ids, timestamps with time zone, every foreign key states `onDelete` and has an index, and a row reached from an unauthenticated URL carries a random `token`.

**One store ([FER-038](../tickets/FER-038-single-store.md), decided 2026-11-16):** `store` holds exactly one row, which the database enforces and the migrations create; every other table keeps its `storeId`. The code no longer reads `store`'s `slug`, `isDefault`, `isActive`, `logoUrl` and five colors, `store_member`, or `user.role`'s two values; [FER-041](../tickets/FER-041-drop-unread-schema.md) drops the columns and the table, and makes `admin` the role's one value, once no deployed build reads them. [FER-020](../tickets/FER-020-home-curation.md) adds `announcement` and `announcement_translation` (text, optional link, active switch, dates) and a position for each banner among the home's rows.

`locale` is an enum: `es`, `en`. Every table has `createdAt` and `updatedAt` unless noted.
