# Design guidelines

The craft layer for every user-facing surface. `AGENTS.md` wins where it rules (component contract, definition of done, testing); this file wins over the generic `frontend-design` and `web-design-guidelines` skills. Rules name a reference implementation when one exists. Read it before UI work.

## Philosophy

Two people use this product, and neither is at a desk. A **fair shopper** stands at a street stall holding a phone in one hand, on mobile data, often in sunlight: they scan a QR code or open a link sent by WhatsApp, look for an article, check its price and order it with a name and a phone number. A **store owner** loads articles from the same kind of phone, between customers: photos first, then a few fields, and it has to take under a minute. Later they check the orders that came in. Design for those two jobs, phone first: one thumb, large targets, the price and the next step in the first viewport, nothing that needs a hover or a second hand. Precise, calm, honest; confidence through clarity, never decoration. When requirements compete, protect in order: correctness of displayed facts (a polished screen with a wrong value is a defect) → the browser floor and the system → the user's task → consistency → composition → polish.

Answer first, records below; one claim, one home. Ask only when the answer changes meaning (amounts, states, permissions); visual craft is settled here.

**Process.** Frame the job (who, deciding what, which edge state changes it; never invent data). Choose the composition: the first viewport is the task, tables for lookup, charts only when a relationship reads faster; blurred or with the words masked, the hierarchy still reads. Build with the system. Inspect in light and dark, at 375 px and desktop, against the definition of done.

## Foundations

**Tokens.** `src/styles/globals.css` is the API (Tailwind 4, CSS-first). Use utilities or `var()`; never a hex/`oklch()`/`hsl()` literal in a component, a parallel token, or an ad-hoc restyle of a shadcn primitive. Roles: `background`/`foreground` canvas; `card`/`popover` raised surfaces; `sidebar` (with `-foreground`, `-accent`, `-border`) the admin's chrome and the grey canvas its cards sit on (§ Admin); `primary` the one emphasized action per view; `secondary`/`muted`/`accent` quiet fills, `muted-foreground` captions; `destructive` danger and errors; `border`/`input`/`ring` boundaries and focus; `chart-1…5` the only series colors.

Radius `rounded-md` controls, `rounded-lg` cards and dialogs. Shadows by role: `shadow-xs` controls, `shadow-sm` cards, `shadow-lg` overlays. Fonts only through `next/font` in `src/app/[locale]/layout.tsx`. Both themes are first-class: every color recipe carries its `dark:` half.

**Browser floor.** Tailwind 4's: Chrome/Edge 111, Safari 16.4, Firefox 128; its colors need `oklch()` and `color-mix()`. SWC transpiles syntax but never polyfills built-ins, and browserslist doesn't police methods: check a built-in (`Object.groupBy`, `Promise.withResolvers`, iterator helpers) against the floor. Verify floor-sensitive changes on `pnpm build` output, not dev. An older floor is a project decision with its own CSS fallback pipeline and a test.

## Typography and copy

| Role                    | Classes                                                   |
| ----------------------- | --------------------------------------------------------- |
| Page title              | `text-lg md:text-xl font-semibold`, the single `h1`       |
| Decisive value          | `font-semibold tabular-nums`; `font-mono` for identifiers |
| Body                    | `text-sm`                                                 |
| Prose; inputs on mobile | `text-base`                                               |
| Caption, helper, badge  | `text-xs text-muted-foreground`                           |

No arbitrary sizes or off-scale weights; text that doesn't fit is rewritten or reflowed, never shrunk. Aligned figures are `tabular-nums`, right-aligned, peers at equal precision. Numbers, prices and dates go through `src/lib/utils/format.ts`, which owns the time zone (the store's, `America/Montevideo`) and the cached `Intl` instances; every formatter takes the page's locale as an argument, and components never build `Intl.*` or call `toLocaleString()`. A price names its currency: `$ 1.290` and `US$ 12,50` in Spanish, `UYU 1,290` and `USD 12.50` in English, cents only when the amount has any.

**Two product languages: Spanish by default, English behind a toggle**, in the storefront and the admin alike. The URL decides: no prefix is Spanish, `/en/...` is English, and `<html lang>` follows it. No interface text is written in a component: every string, hidden ones included (sr-only labels, `aria-label`, placeholders, toasts, validation messages), lives in `src/content/{es,en}/` and reaches the screen through `getDictionary(locale)` or `useDictionary()`, so both languages always have it (`docs/agents/i18n.md`). Spanish uses the Rioplatense voseo ("Probá de nuevo"). The language switch (`molecules/locale-toggle`) is a pill like a light and dark switch: a rounded-full capsule with `ES` and `EN`, a filled thumb under the current language. It is a link to the same page in the other language, keeping the path and the query string; its accessible name is the language it leads to, in that language, with `lang` on the link ("English", "Español"), and its description names the current one in the page's language ("Idioma actual: español"); the codes are `aria-hidden`. A 44 px target on a phone, focus drawn on the capsule. Code, comments, commits and test titles are always English. Sentence case; no all-caps eyebrows (the storefront's display face is all caps: § Storefront). Headings state the task or fact; a toast says what happened. Never show raw `error.message`, enum values or schema field names.

## Color and surfaces

Monochrome first. Color encodes state, action or data, always with a non-color cue. Earned color uses these recipes only:

- Status chip: `bg-{hue}-100 text-{hue}-800 dark:bg-{hue}-950 dark:text-{hue}-300`.
- Tinted panel: `border-{hue}-200 bg-{hue}-50 text-{hue}-900 dark:border-{hue}-900 dark:bg-{hue}-950/30 dark:text-{hue}-100`.
- Good/bad (not up/down): `text-emerald-600 dark:text-emerald-400` / `text-red-600 dark:text-red-400`.
- Hues: amber attention, red error or blocking, emerald success, blue information. Text on a colored fill gets its AA ratio in a comment.

**Environment identity.** Every non-production deployment carries `molecules/environment-marker`: a 2px top line and a chip naming the environment, never color alone. Production carries nothing; a bare edge means the real thing.

One canvas: a card or border must express interaction, selection, warning or a grouping spacing can't. No cards in cards. Busy: remove content. Loud: less color, weight and borders. **Hard rejects:** decorative gradients, gradient text, glows, textures, glass (`backdrop-blur` on translucent fills), colored side rails, ornamental shadows.

## Layout and responsive

- One page container per shell; constrain blocks, not the page (forms `max-w-sm`, as the sign-in view in `src/app/[locale]/page.tsx`).
- Mobile-first. Grid/flex children get `min-w-0` (`atoms/input`); so does a `<fieldset>`. The page never scrolls sideways: wide content scrolls in its own `overflow-x-auto` box, with `overflow-y-clip` to avoid a phantom vertical bar.
- Toolbars `flex-wrap`; titles `truncate` on a block element. Unbounded user text never sits in a `whitespace-nowrap` control. `sticky` binds to the nearest ancestor with any `overflow`.
- Overlays cap height with `dvh`, not `vh`. Inputs are `text-base md:text-sm` so iOS doesn't zoom. Never lock zoom or orientation.
- Below `md` every control is a 44 px target: `atoms/button` (every size but the two `xs`) and `atoms/input` carry it, and so do menu items and a dialog's close button; a control drawn by hand takes `h-11 md:h-9` or `size-11 md:size-9`.

## Data

**Four distinct states:** pending (skeleton with the real geometry, `aria-busy`), error (`role="alert"` plus retry when it can succeed), empty (a short sentence and optionally the action that fills it), data. A failed query never renders as empty or zero. Spinners only for unknown-length inline waits; no "Loading…" text.

- Keep the previous result while the next page or search loads (`placeholderData: keepPreviousData`); never unmount what the user is aiming at.
- Tables: numeric headers align with their values; `aria-sort` on sortable headers; totals in `<tfoot>`; paginated lists sort on the server with an `id` tiebreak.
- Charts: `--chart-*` colors, the shared formatter, no animation under reduced motion, exact records reachable.
- Native controls first (`<input type="date">`). Shortcuts are stored as `Mod+K`-style tokens, rendered by one formatter.

## Interaction, forms and feedback

**Forms:** `<Form>` + react-hook-form + `zodResolver`; `Field` for layout only, ids wired by hand.

- **Never discard typed input.** Reset only on success (`onSuccess`, or after `mutateAsync` resolves); a failure keeps the text and says why. Never silently clamp or default.
- After a save, `form.reset(storedRow)` and key the form by entity: react-hook-form ignores new `defaultValues`.
- An error on a hidden tab or step brings the user to it; `noValidate` so zod owns messages.
- **Numeric inputs** hold `number | null` and emit `null` when cleared; callers use `?? current`, never `?? 0`; the schema rejects empty before coercing. What is typed is read the same in either language, whatever keypad the phone shows (`readTypedNumber`): one separator before one or two digits is the decimal point, before three it groups thousands, and a figure that could be read two ways is refused with its reason under the field once focus leaves, never guessed. On blur the field shows the value in the page's notation (a decimal comma in Spanish, a dot in English).
- **Narrow Radix values:** `onValueChange` returns any string. `safeParse` it and ignore unknowns and the `""` echo.
- Never ask users to type internal ids; don't prefill fields that decide money or dates.

**Every action answers.** Pending: `disabled` and a progressive label ("Saving…"). Every outcome is visible (toast or inline `role="alert"`), success only after it happened. Destructive actions confirm in a dialog; dangerous ones add a typed phrase. A toast is for the user; reporting is separate (`AGENTS.md` § Error reporting). Success effects go in `onSuccess`: `onSettled` runs on failure too, and `mutate()` callbacks wait for it.

**Focus after close.** When a dialog or popover closes, focus lands on the trigger or the next likely control; a controlled dialog without a trigger sets it in `onCloseAutoFocus` (or `onOpenChange` when the exit delay matters). Auto-focus never fires on a timer while `document.activeElement` is editable. Never remove a focus ring without an equivalent.

**Tooltips over `title`.** The name stays on `aria-label`; the tooltip repeats it. A disabled button sits inside a `<span>` trigger so the tooltip explaining why still shows.

## Motion

Stillness by default. Approved: `animate-spin`/`animate-pulse` for waiting, Radix open/close via tw-animate-css at 150–300 ms (200 default), `transition-colors`, and the language pill's thumb, which slides to the other language in 200 ms before the page navigates (a plain click only; under reduced motion it does not slide and the link navigates at once). Reduced motion per driver: CSS with `motion-reduce:`, JS with the library's hook. Under reduced motion, drop overlay exit animations instead of slowing them: Radix unmounts an overlay when its exit animation ends, and one that never ends leaves an invisible layer eating clicks. Never scroll-reveal, parallax, marquees, bounce or sound; the storefront reveals on scroll, and its cover and the coming-soon marquee move on their own (§ Storefront), and the admin's orders screen has one sound: a short beep when an order arrives, off until the staff turns it on with a toggle (`aria-pressed`), remembered per browser, silent where Web Audio is missing (`useOrderSound`); a choice remembered as on, on a page the browser keeps silent until a gesture, shows a hint beside the toggle until the first tap or key wakes it; an arrival before then is not beeped, nor kept to beep when the sound wakes.

## Storefront

The public store speaks another visual language than the admin: a lime announcement bar, a dark moss header with the logo in the middle, a white page, articles on grey tiles, wide heavy headings (FER-039, after the structure and feel of https://landonorris.store, never its logo, photos or licensed typeface). Everything above still holds there except what this section changes. The admin changes nothing: it keeps the calm back-office rules.

**Where it applies.** Storefront components are the `store-*` directories of the three component tiers, plus the shared `molecules/carousel` they build on; storefront routes are listed in the `storefront-style-outside-storefront` ratchet (`scripts/ratchets.json`), today `/design`. That ratchet fails any storefront utility used anywhere else, so a storefront route keeps its styles inside `store-*` components and only places them. `/coming-soon` renders `organisms/store-coming-soon`. The store's pages (`src/app/[locale]/(store)/`) sit on `organisms/store-theme`, the canvas the group's layout draws, and each renders its own frame, `organisms/store-frame` (the bar, the header, then the page), and its footer, because the bar's words and the header's categories come from the database, which the prerendered layout must not read (`docs/agents/nextjs.md` § Store pages). Inside: `organisms/store-intro` (the home, until FER-022), `organisms/store-catalog`, `organisms/store-article`, `organisms/store-cart-panel` (the cart's side panel, in every page's frame, FER-045), `organisms/store-checkout` (`molecules/store-cart-line`, `molecules/store-checkout-form`), `organisms/store-order` (an order's page, FER-026, FER-051: the moss banner with its code; the read-only steps, `molecules/store-order-stepper`, across under the banner from `md` up and down at the end of the order, above its buttons, below it; what happens next, the status in words, the lines, the note; the buttons centered; then `molecules/store-article-band`, apart from the order by a margin above and below; then an article row, "Hacé todos los pedidos que quieras", of one category drawn at random per visit among those with four or more published articles, else any with one (`pickReorderCategory`, `src/lib/catalog/reorder.ts`): the page reads per request, so the server draws it and the browser only shows it), `organisms/store-status-page` (a miss or a failure). `molecules/store-order-stepper` is the admin's `molecules/order-stepper`, read only, `tone="bare"`: reached steps moss with a lime icon, the current one ink with an outline, the ones to come dashed hairlines, the detour `store-danger` with the background's ✕, the names in the display face. A component the app and the storefront share takes a neutral mode instead of storefront classes (`LocaleToggle`'s `tone="bare"`, styled by `molecules/store-locale-toggle`). A storefront dialog renders in place, not in a portal (the search panel sits under the header that holds it). The exclude list is not the door for a new route: the ratchet's baseline check rescans with the rule as it was on the base branch and fails a PR that widens it. `/design` shows every storefront component in both languages and answers 404 in production: check a storefront change there at 375 px and 1280 px.

| `store-surface`    | `#f3f3f2` | The tile behind an article's photo, quiet fills; the foreground on it is 16.4:1                                                            |

`store-muted` (small text on the page, 6.3:1, and on the tile, 5.6:1), `store-contrast-muted` (small text on the moss, 8.7:1) and `store-line` (hairlines only, never a fill behind text) are derived from those five with `color-mix()`, so the theme file never supplies them: `<body>`, which holds the five, carries `data-store-palette`, which computes the three there (a custom property is inherited as a finished color). The accent is a fill, or text on the moss (the header's links, the footer's headings, icons); never text on the page or the tile, where it cannot be read. Text on the accent is `store-foreground`; text on the moss is `store-background` or `store-accent`. Opacity steps of the five are the only other colors, for a hover on the moss (`hover:bg-store-accent/15`), a scrim (`bg-store-foreground/50`) and a hairline on the moss (`border-store-background/15`). The theme file's test (`src/styles/theme.test.ts`) fails unless every pair above reads. The storefront has no dark theme: the store's palette is its identity, so these tokens have no `.dark` value and storefront markup never uses the app tokens (`background`, `primary`, `muted-foreground`).

**Type.** Two faces, both through `next/font` in the root layout. The display face is Anybody, variable, at 135% of its width (the theme's `--font-display--font-variation-settings`), always `font-display font-extrabold uppercase`: headings, article names, navigation, buttons and labels; never a sentence of body copy or a price. Geist sets prices and body copy, in sentence case (prices `tabular-nums`, regular weight). Labels in the display face (navigation, buttons, card names, the bar, legends) are `text-xs`; display sizes are fluid utilities, not the admin's type table: `store-display-hero` (36 px on a phone to 88 px), `store-display-banner` (28 to 54), `store-display-page` (28 to 46: a page's title), `store-display-article` (20 to 28: an article's name on its page), `store-display-section` (18 to 28: a row's heading), `store-display-search` (16 to 40: the search field, never under 16 px so iOS does not zoom), `store-display-figure` (48 to 72). **Motion.** The storefront moves, within these rules:

- Only `transform` and `opacity` animate (and colors on hover).
- Every motion has a reduced-motion answer: CSS behind `motion-safe:`/`motion-reduce:`, scripted motion behind `usePrefersReducedMotion()`. Reduced motion shows the final state at once: the marquee wraps in place, reveals do not hide anything, the count-up shows its figure, a carousel jumps instead of gliding, the cover stays still.
- The text is in the server's HTML and visible without JavaScript. Motion lives in small client components (`store-reveal`, `store-count-up`, `store-marquee`, the carousels) that wrap server-rendered content. `useScrollEntry()` holds back only what is still off screen after hydration, so nothing the visitor has seen blinks; what was on screen at load is not animated.
- A row and the gallery move only when asked: they never move on their own. A row never loops; the article's gallery goes round (FER-045).
- The cart's side panel (FER-045) answers an add, quickly: it slides in from the right in 300 ms as its scrim fades in, and both leave in 200 ms (at once when a link inside is followed); the line just added rises 12 px into place under a lime wash (`store-accent/30`) that holds a moment and fades within two seconds; the count in its title bumps once when adding opened it or a quantity grows, and the header's badge bumps when it shows more than it last showed in sight. Transform and opacity only (`animate-store-panel-in`, `-scrim-in`, `-rise`, `-wash`, `-bump` in `src/styles/globals.css`), every one finished by itself in under two seconds. Under reduced motion none of it runs: the panel and its scrim appear and leave at once (the dialog rule in `globals.css`), the line is not washed and nothing bumps.
- One thing per store page moves on its own: the cover (`molecules/store-cover-carousel`, a new banner every six seconds), on an article's page its festive band, or on the coming-soon page the marquee. Motion that runs longer than five seconds needs a way to stop it (WCAG 2.2.2): the cover has dots and a pause button (`aria-pressed`) and holds still while hovered, focused or dragged; while it moves its banners are not announced (`aria-live="off"`), once still they are, politely. Under reduced motion it never moves and offers no pause; one banner shows still, without controls. The marquee carries its own pause.
- A finite flourish is not "moving on its own": the heading's rise and a burst of `molecules/store-bubbles` (blown on load and on each press of its content, gone in under five seconds, so it needs no pause) end by themselves.
- The article's festive band (`molecules/store-article-band`) moves on its own as long as it is on screen, so it carries a round pause button in its corner (`aria-pressed`, 44 px, named in both languages), remembered for the visit (`useSessionFlag`, `sessionStorage`). Pausing sets `animation-play-state: paused` on every piece, so nothing jumps; off screen (`useOnScreen`) and before the script runs it holds still too. Under reduced motion nothing is animated, the streamers rest around the greeting, and the button is not shown. A piece's duration and delay go inline, never in a custom property the `--animate-*` theme value reads, which resolves on the root.

**Still banned in the storefront:** decorative gradients and gradient text (the banner's shade, rising from the bottom so white words read on any photo, is the one gradient, and it is legibility), glows, glass (`backdrop-blur` on translucent fills), textures, parallax, bounce, sound, and any color outside the five tokens, the danger one, their three derivations and the opacity steps above.

## Accessibility

WCAG AA in both themes. Landmarks, one `h1`, ordered headings, source order is reading order, a skip link per shell. Focus rings: controls as `atoms/button`, large regions `focus-visible:ring-2 focus-visible:ring-ring`. `aria-live="polite"` for status, `assertive` only when blocking. `role="combobox"` triggers carry `aria-controls`. Never color alone.

## Anti-patterns

A centered hero over a card grid; rows of interchangeable metric boxes; badges for ordinary metadata; borders repairing weak hierarchy; charts without a question; a narrow table stranded in a wide section. Restraint is not sterility: keep one focal point and quiet the rest.

## UI definition of done

`AGENTS.md`'s gates apply. On every interactive widget added or touched, check by hand what lint can't:

- A styled toggle has `aria-pressed`.
- The active step or page has `aria-current="step"`/`"page"`, else `undefined`.
- An icon-only control has an accessible name; in a list the name carries the row's identity ("Borrar categoría: Anillos"), or screen readers and name-based locators can't tell rows apart.
- No nested interactives: one interactive element per stack, siblings otherwise.
- Never lock zoom (no `maximumScale`, no `userScalable: false`).
- A field error has an id and `role="alert"`; the control points at it with `aria-invalid` + `aria-describedby`.

Then review in order, worst systemic defect first: first read → composition → typography → evidence → restraint → themes and reflow (light, dark, 375 px, reduced motion) → trust and access.

## React and browser pitfalls

- **Hydration:** a client component's first render matches the server's: no `Date.now()`, `Math.random()`, `window` or time-zone-dependent formatting in it. Seed client state from the server; a skeleton matches its page's markup.
- **Global key handlers ignore typing:** return early for inputs, textareas, selects and contenteditable; guard `typeof e.key === "string"` (autofill sends keyless events); data-changing hotkeys do nothing while a dialog is open.
- **A modal owns Escape:** Radix closes in the capture phase, so a global handler then sees cleared state; call `stopPropagation()` in `onEscapeKeyDown`.
- **DOM handlers never throw:** a handler error skips error boundaries and hits `window.onerror`. `safeParse`, not `parse`.
- **URL state is untrusted:** parse and clamp at the point of use (`?page=0`, `?pageSize=500`); unknown enums fall back to "all"; every accepted param reaches the query. Await a deferred URL setter before navigating. Never take context from "the first row" or a stale cookie.
- **`queryFn` never resolves `undefined`:** TanStack Query v5 fails the query. Return `null` or throw NOT_FOUND (Drizzle's `findFirst` returns `undefined` on a miss).
- **Global mutation handler + local catch = duplicate toasts:** one layer owns the message; opt out through `meta`.
- **Promise-returning browser APIs need `.catch`:** `navigator.clipboard.*`, `media.play()`, `wakeLock.request()` reject under browser policy, and a sync `try/catch` around an unawaited call sees nothing.
- **Review autofixes:** destructuring can detach a method (`const { get } = searchParams` throws).
